# DIG Financial Fraud Lab

Defensive and simulation-only specialization for banking, card payments, fraud detection, and risk analysis.

## Scope
- Card transaction lifecycle: authorization, clearing, capture, settlement, reversals, refunds, chargebacks.
- 3-D Secure, AVS, CVV/CVC, tokenization, network tokens, device and session signals.
- Account takeover, card testing, synthetic identity, first-party fraud, friendly fraud, mule activity, merchant abuse, transaction laundering, refund abuse, promo abuse.
- Fraud analytics: rules, anomaly detection, velocity features, behavioral signals, graph features, explainability, calibration, false-positive control.
- Incident response: triage, evidence preservation, containment, customer protection, merchant review, root-cause analysis.

## Training loop
1. Generate a synthetic transaction or account scenario.
2. Fraud Analyst scores risk and explains signals.
3. Red-Team Simulator attempts to evade the detector in a closed synthetic environment.
4. Detection Engineer updates features/rules/model strategy.
5. QA measures precision, recall, false positives, false negatives, latency, and stability.
6. Successful lessons go to the Experience Bank; failures go to the Failure Bank for retesting.

No real card data, credentials, stolen payment instruments, live merchant targeting, or instructions for committing fraud are used in this lab.
